# 深度 PTC 模式

[English](README.md) · MIT · 当前版本 **1.9.2**

[更新日志](CHANGELOG.md) · [测试报告](TEST_REPORT.md) · [插件协作与验证范围](COMPATIBILITY.md)

深度 PTC 是 DeepSeek Harness 的 Agent 模式，支持进度汇报、澄清提问、按任务规模制定计划，以及可插话的后台任务。它以已安装的官方 PTC 预设为基础，提供可选执行环境、按需加载工具和 Skill，以及面向第三方插件的两层预设身份适配。

面板位于对话区侧边，包含执行环境、子代理、后台任务、输出文件、SSH 连接和工具状态。输入框下方保留小胶囊，用于展开和收起面板。设置里有独立的「深度 PTC」页。界面特效采用轻量渲染，检测到外观插件时默认关闭。

## 五个基本问题

| # | 基本问题 | 深度 PTC 的做法 |
| --- | --- | --- |
| 1 | **闷头干活不汇报** | 每次 `run_code` 前一句话说明要做什么；里程碑稍长汇报；连续两三个工具调用必须出声；任务结束简短列出结果、失败工具与来源。 |
| 2 | **有歧义先猜不问** | 意思归用户、事实归工具：不认识的名称、多个可能目标、技术路线、范围和验收标准不确定时，先问 1–3 个带选项的问题，推荐项在前；不认识的词先问你，你也不知道时才自己查证；可检查的事实自己查。你的说明优先于模型的既有认识，不擅自换方案，多项请求逐项核对，不虚报验证结果。 |
| 3 | **执行中休眠、失联** | 由代码强制：前台等待超过 30 秒自动转后台且不杀命令；你发消息时正在等待的命令约 2 秒内转后台，模型立刻看到消息；前台超过 5 秒的 sleep/Start-Sleep 直接拒绝；job 完成自动唤醒模型。 |
| 4 | **不做计划或计划不可见** | 按预计耗时分档：≤5 分钟内部计划直接做；5–20 分钟先展示计划，不等审批就执行；>20 分钟先给计划、等你批准。估计升档时重新说明；你可以在任一步调整方向，显式 plan mode 优先。 |
| 5 | **没用好简洁上下文与 unlimited token** | 预设从官方 PTC 现场派生，继承官方简洁组合；工具目录精简、完整 schema 按需加载，避免上下文被工具定义撑爆；人设写明本模式 token 预算无限、把预算花在读取/搜索/命令/验证上，同时禁止注水和啰嗦。提示词不改变实际计费或 token 上限。 |

## 按“一切皆插件”做的进一步能力

### 1. 预设与工具的动态读取

运行时读取宿主正在发布的官方 PTC 声明，官方行原样继承；仅替换 persona、执行组、可达性守卫、job 与提问包装。在设置变更时、以及每个深度PTC对话创建或恢复之前确认一次声明，仅在声明或配置变化时重建，不再定时轮询；声明读不到/解析失败才用随包快照并记录日志。官方升级后无需为本模式发版即可继承新工具；新建会话使用新版，已有会话不强制切换。

### 2. 创造模式工具的灵活加入

插件实验台随会话始终开启，读取宿主正在发布的创造模式，只追加相对 PTC 多出来的行，专门负责 DSH 本身的插件创造。模块名保持创造模式原文，官方改名时跟着宿主走；技能目录按创造模式文件位置解析。实验台包只留在本进程内存，不写仓库、已发布预设、桌面组合或插件源码，经宿主原有批准后运行。加载只读预设清单和文档，不调用 `composedPreset`。

### 3. 适配 dsh-go 的界面控制

屏幕控制工具留在初始 PTC SDK，不收进按需目录，失败后也不隔离。识别依据是工具自己的 `resident` 标记、`dsh-go/view`、名称或提供者标记；不声明 dsh-go 自己的槽位，也不替换它的设置表单。工具状态控件投影失败时留空，不拆输入区或屏幕控制界面。

### 4. 扩展不同环境的适应范围

支持 WSL Bash、PowerShell（含 5.1 与 7 的可执行文件选择）、Zsh、原生 Bash。只对本模式生效，不改全局 shell；沙箱、审批和进程管理仍用官方实现。WSL 目前仅支持宿主已授权的 `danger-full-access`。

### 5. 外部插件工具与工作流

这是深度 PTC 的核心接口：外部插件按自己的契约发布工具，深度 PTC 负责发现、按需加载、隔离故障，并在失败时回到官方 PTC。外部插件需支持当前宿主，并在 `deep-ptc` 作用域中发布工具；深度 PTC 不把任何插件写成依赖，也不替换执行器。

通过 `composedPreset` 查询预设的第三方插件使用同一套兼容规则。以实测的 dsh-ops 为例，它只认 `minimal/standard/ptc/cordis`，所以在深度 PTC 会话里收到兼容 ID `ptc`，宿主实际挂载的仍是 `deep-ptc`。只有能明确归属的外部工具才会进入故障隔离。

### 6. Skill 与工具的读取流程优化

每轮结束还会给出 Skill 上下文卡片：只列当前仍加载、未关闭的 Skill，用户决定下一轮继续保留还是移除。

先搜摘要，再加载完整 schema：默认每页 6 项、最多 8 项；完整 schema 每次最多 6 个、总预算 16 KB；最多保留 12 个近期选择。故障按对话隔离：明确不可用立即禁用；临时错误连续 3 次才禁用，成功一次清零；参数错误、权限拒绝、业务失败不算故障；一键重载只清当前对话。Skill 两阶段：目录只查元数据与权限，正文交给官方 `skill` 工具，检索不读正文。

安装插件，在 **设置 → 深度 PTC** 选择执行环境，然后新建会话并选择 **深度 PTC 模式**。

## Skill 上下文卡片（1.8.5）

每轮对话结束后，对话区里这一轮的末尾会显示一张卡片（和官方计划卡片同一位置），只列出**当前仍在上下文中、且没有被关闭**的 Skill，不列全量 Skill 目录。每项包含名称、描述和滑动开关，默认是开；顶部有“全部保留 / 全部关闭”，标题下会提示有几个将在下一条消息后移除。超过 4 个时折叠，可展开全部。卡片只出现在最新一轮，不会在历史轮次里重复。

- 开关只改变下一轮的选择，发送下一条消息时固定；新 turn 的第一个模型步骤前生效。
- 保留的 Skill 正文继续留在上下文，不重载；关闭的 Skill 把 tool result 正文替换成一句占位，持久日志和人类 transcript 仍保留完整原文。
- 关闭并移除后，该 Skill 不再出现在后续卡片中，直到模型重新加载它。
- 模型如果在新任务中确实需要它，重新调用 `skill` 即可；卡片会在该轮结束时重新列出。
- 卡片状态在插件根部注册，因此升级后已有的 Deep PTC 会话也会从历史事件重建，不需要新建会话。
- 卡片会跟踪官方 `skill` 工具直接加载，以及 `run_code` 内 PTC 子调用加载的 Skill；后者通常只进入程序而非模型上下文，关闭时只从卡片移除，不重写程序输出。`/name` 注入暂不纳入。
- 切换开关不会在对话里留下命令回显（会话日志仍记录这次操作）；只有切换失败时，原位显示一行错误。

## 面板、设置页与界面特效

Deep PTC 的模式名称、设置页和会话界面会随 DSH「设置 → 通用 → 语言」在中文和英文之间切换。所有入口都使用 DSH 的官方扩展点，不改宿主布局，也不注册快捷键。

- **设置 → 深度 PTC**：执行环境与 Shell、界面特效开关，以及可复制的诊断信息（反馈界面问题时附上）。
- **对话侧边的「深度 PTC」面板**。空间充足时默认显示，并随对话区尺寸调整。原生侧栏全屏覆盖对话时会隐藏，窄屏可通过下方胶囊展开。
  - **执行环境**：WSL、PowerShell、原生 Bash 或 Zsh，对之后新建的深度 PTC 会话生效。
  - **子代理**：名称、状态、用时和 token；点击在官方右侧栏打开该子代理的对话。
  - **后台任务**：最多六个位置，运行中优先且最多五条，已结束最多三条，超出部分合为一条可展开记录。
  - **输出文件**：本会话写入或交付的文件，最新的在前；最多三个位置，超出时折叠占一个位置。规则与 DSH 官方的交付卡片一致，并包括 `run_code` 里写入的文件。
  - **SSH 连接**：本会话连接过的主机（成功或失败）与 `~/.ssh/config` 中的主机别名。
  - **工具状态**：“重载所有工具状态”按钮，以及调用失败的外部工具（如有）。
- **输入框下方的小胶囊**显示执行环境、子代理数和工具提醒，点击展开或收起独立的侧边面板。1.9.0 保存的旧侧栏页签会显示迁移提示。

界面特效**只在当前显示的是深度 PTC 会话时生效**：更克制的明暗配色与字体、输入框聚焦细线、蓝色渐变发送键、淡蓝用户气泡、指针追光、点击涟漪、磁吸发送键；运行时输入框发光、发送键光环和输入框上方的光点。

- 轻量渲染：特效样式直接作用于 DSH 自带的稳定属性，不再逐帧计算元素样式；循环动画只改变透明度或位移；光点画布只覆盖输入框附近，像素密度上限 1.5，无动画或窗口隐藏时停止绘制。
- 检测到 dsh-claude-style、dsh-refined-ui 等外观插件时默认关闭特效；你手动打开后保留你的选择。dsh-refined-ui 运行时始终不重复绘制。
- 全部遵循系统的“减少动态效果”。

## SSH

深度 PTC 通过当前执行环境的 Shell 调用本机 OpenSSH 客户端连接外部主机，不另建传输。模型会收到本机客户端位置、`~/.ssh/config` 里的主机别名（只读取名称、地址、用户和端口，不读取密钥），以及使用规则：始终非交互（`BatchMode=yes`、连接超时），不打开交互式远程 Shell，不等待密码或主机密钥确认；认证失败时停下来告诉你，不换凭据、不关闭主机密钥校验；长时间远程任务转为后台任务。WSL 环境中 SSH 在发行版内运行，使用发行版自己的 `~/.ssh`。

面板可复制常规 SSH 检查命令，也可按需复制 DSH Go 的连接资料。前者用于日常远程主机检查，SSH、SCP、SFTP 和端口转发仍采用 OpenSSH 的工作方式。DSH Go 可在 POSIX 远端托管启动 `dsh web`，Windows 远端使用连接已有服务的方式。端口以实际服务启动结果为准，认证在客户端配置。这里的复制按钮只准备资料。

DSH 允许尚未开始首轮的空白会话重新选择预设，首轮开始后会锁定。Deep PTC 的命令门禁读取宿主当前选择，与界面使用同一份状态。

## 1.7.2：轻量、按需、可恢复的工具调用层

本版增加一个工具与 Skill 的目录入口 `deep_ptc_tools`，具体任务继续交给外部插件和当前官方 PTC 工具完成。

- **先搜摘要，再加载定义。** 本地元数据检索优先返回外部工具，未找到匹配项时返回官方候选。默认每页 6 项，最多 8 项；完整 schema 每次最多加载 6 个、总预算 16 KB。普通官方工具继续可用，额外工具按需进入宿主生成的 PTC SDK，最多保留 12 个近期选择。
- **确认损坏才禁用。** 工具明确不可用（如模块缺失、接口不存在、声明不可用）时立即禁用；临时错误和原因不明的失败连续 3 次才禁用，中间成功一次就清零。参数错误、路径错误、权限拒绝、取消，以及工具正常返回的业务结果（如“构建失败”）都不算工具故障。官方工具不参与禁用，包括配置根层的官方工具（如 `lsp`、`terminal_*`）。禁用后由程序拦截后续调用，故障记录随对话保存；切换 agent、恢复对话或重载插件不会自动解除。调用开始时捕获来源和状态代次，用户重载前的迟到结果不会污染新状态。普通空结果、分页续读和命令非零退出同样不算故障。
- **任务优先，不查坏工具。** 输入有误就改正，临时错误最多重试两次；工具一旦被禁用，就尽快改用其他可用同类工具或官方工具，不再探测、重试或查根因。仅在写入或命令可能已部分完成时核查必要的任务状态，避免重复操作。
- **完成时简报。** 模型结束任务时简短列出失败工具与已声明的插件来源；程序同时在回合结束后生成可展开的“工具适配提醒”。来源不明就列工具名，不猜插件身份或故障原因。
- **一键重载。** “重载所有工具状态”仅清除当前对话的故障标记与按需加载选择；不调用模型，也不停止正在运行的任务。另有用户命令 `/deep-ptc-reset-tools`。工具状态和这条命令与 Skill 卡片一样在插件根部注册，闲置的会话里也能用。
- **Skill 两阶段调用。** 目录只查询宿主已解析的技能元数据和调用权限；选中后使用官方 `skill` 工具加载正文并遵守完整指令，复用上下文中已有指令。检索不读取 Skill 正文。

```js
// 在官方 run_code 中使用；这些操作本身不会执行搜索到的任务工具。
const matches = await tools.deep_ptc_tools({ action: 'search', query: 'search files' });
const loaded = await tools.deep_ptc_tools({ action: 'load', names: ['实际工具名'] });
const skills = await tools.deep_ptc_tools({ action: 'skills', query: 'build test' });
// 之后按返回的真实 schema 调用工具，或通过官方 skill 加载选定技能。
```

可在 `deep-ptc-settings` 设置 `compactToolCatalog: false` 保留完整宿主 SDK，故障禁用与重载机制仍工作。`toolCompatibility: false` 则停用整套新增调用层。`toolPreferences` 继续支持对已有工具的可选优先关系。

精简只作用于当前官方渲染器生成且未被其他插件改写的 SDK 段；插件自建 SDK 继续由其自身加载器管理。外部插件仍须支持当前宿主并在 `deep-ptc` 作用域发布工具；本层不会绕过工具隐藏、授权或接管被卸载的整个执行器。未进行实际 OPS/在线模型端到端评测。



## 代码层强制：不休眠、随时可插话

「不 sleep、不干等」不只写在提示词里，1.5.0 起由插件代码强制执行，由运行时执行以下已覆盖的规则：

| 场景 | 代码行为 |
| --- | --- |
| 前台命令跑得久 | 超过 **30 秒**（可配置 5–600）自动转为后台 job，命令不会被杀掉；模型请求更长的 `timeoutMs` 也会被压到这个上限 |
| 命令运行中你发了消息 | 约 2 秒内结束前台等待，命令转入后台继续跑，模型立刻看到你的消息；job 完成后仍会自动唤醒模型 |
| `job_output` 等待 job | 等待上限同为 30 秒；你一发消息就提前返回；你的消息未读时再次等待会被拒绝 |
| 模型写 `sleep 60`、`Start-Sleep 30`、`timeout /t 20` | 前台超过 5 秒的暂停直接拒绝（`run_in_background` 的命令不受限）；`sleep 1` 这类就绪循环照常 |
| `run_code` 程序里 `setTimeout`/`setInterval`/`time.sleep` | 仅拒绝能静态确认超过 5 秒的实际等待；未知时长放行；同一程序里轮询同一个运行中 job 超过 3 次也会被拒绝 |
| `ask_user_question` | 改为限时模式：默认等 120 秒，最多 300 秒，`-1`（无限等）被拒绝；超时后问题变为「待回答」，你之后的回答会作为消息送达；你不点卡片、直接打字回复，也会立刻结束等待 |

这些规则只作用于「深度PTC模式」会话，不影响其他模式。前提是桌面端设置里「忙碌时回车」为**插入当前任务（steer）**；若为排队（queue），消息会等整轮结束才送达。

```yaml
- id: deep-ptc-settings
  config:
    foregroundSeconds: 30   # 前台等待上限（秒），5–600
```

## 选择 WSL、PowerShell 或 macOS 工具

安装并加载后，打开 **设置 → 深度 PTC**，选择执行环境并保存，再新建一个 **深度 PTC 模式**会话。

| 选项 | 宿主 | 实际执行方式 / 模型工具 |
| --- | --- | --- |
| 自动 | Windows / macOS / Linux | Windows 选 PowerShell，macOS 选 Zsh，Linux 选 Bash |
| WSL Bash | Windows | `wsl.exe ... --exec bash -lc`，工具名 `bash` |
| PowerShell | Windows | Harness 官方原生 PowerShell 执行器，工具名 `pwsh` |
| 原生 Bash | Windows | 填写 `bash.exe` 的绝对路径，可使用 `dsh-ops` 随包的 Niubash |
| Zsh | macOS / Linux | macOS 用 `/bin/zsh -lc`；Linux 用已安装的 `zsh`；工具名 `zsh` |
| 原生 Bash | macOS / Linux | Harness 官方 Bash 执行器，工具名 `bash` |

不适用于宿主的选项会禁用，运行时配置也会拒绝这些选择。WSL 发行版留空时使用 Windows 默认发行版，也可填写 `Ubuntu` 等已安装名称。Linux 上选择 Zsh 前需要安装 Zsh。

Windows 选择原生 Bash 时，可以填入 `<profile>/node_modules/dsh-ops/runtime/win32-x64/niubash/winuxcmd/bin/bash.exe` 的实际绝对路径。路径不可用时新会话保留官方 Shell。原生 Windows Bash 仅在宿主已授权的 `danger-full-access` 下执行，受限模式请选择 PowerShell。

**选择会改变实际执行器和模型看到的命令语法，不只改工具名称。** 执行器隔离在本 preset 中，不修改全局 shell，也不影响其他 preset。保存设置后，新会话使用新版本；已有会话和后台任务继续使用创建时的环境。切换环境时请新建会话，避免同一任务中途换方言。

WSL 命令使用 Linux/POSIX 语法；文件工具和 `workdir` 仍用 Windows 宿主路径。执行器用 `--cd` 进入目录，发行版、目录和命令分别作为 argv 传递，不额外拼接 shell 字符串。WSL 内的 PATH、代理等由所选发行版的登录 shell 配置决定，Windows 环境变量不会全部自动变成 Linux 环境变量。

### 沙箱边界

原生 PowerShell 和 macOS/Linux 的 Shell 使用 Harness 的沙箱、审批和进程管理。Windows 的 WSL 与原生 Bash 仅在宿主已授权的 `danger-full-access` 下执行，受限模式请选择 PowerShell。

选择 PowerShell、Bash 或 Zsh 时，可以指定本机已经发现的常见可执行文件。留空则沿用官方查找顺序。WSL 仍只选择发行版。所选文件不存在时记一条警告并回到自动。PowerShell 的选择写入官方执行器的 `pwshPath`。Bash 和 Zsh 只改启动参数。

## 插件实验台：官方创造模式，只在内存里试

深度 PTC 经常用来编程，也可以用来设计和试写 DSH 插件。**插件实验台随会话始终开启**，不再提供开关；新建深度 PTC 会话后即可使用。旧 Cordis 配置里的 `pluginLab` 键仅为兼容保留，值会被忽略。

深度 PTC 用和官方 PTC 相同的方式读取宿主正在发布的**创造模式**：走 `agentPresets.readDocument`，优先名称正好是「创造模式」的预设，否则用已随宿主发布的 id `cordis`。只追加创造模式相对当前 PTC 多出来的那些行。模块名保持该预设原文，官方以后改名时跟着宿主走，不把包名写死在本插件里。创造模式技能目录如果写成相对它自己文件的位置，就按那个预设所在目录解析。桌面端已经挂了宿主运行器，这些行留给宿主，不在深度 PTC 里再挂一份。

实验台用来在当前进程里设计和试运行插件：检查当前组合，定义一个通过语法检查的包，再经宿主原有的批准后运行。包只留在本进程内存里，不写入仓库、已发布预设、桌面端组合或本插件源码。宿主的批准保持原样。创造模式预设读不到，或实验工具缺失、失败时，会话继续使用官方 PTC 工具。

## dsh-go 与其他外部工具

Deep PTC 可以把其他插件提供的能力接进同一项任务：用 **DrawAI** 读图、改图并导出 SVG；按需加载**归藏设计**的页面、PPT、图文卡片与文案技能；发现并选用 **Agentero** 的论文和笔记工具；通过 **dsh-ops** 的预设识别使用其执行环境；向 **DSH Go** 提供屏幕工具可用性和 SSH 连接辅助。**dsh-context** 可按当前 Agent 的服务读取 Skill 信息，便于检查上下文。

1.9.2 修复了 DrawAI 等编辑器因版本过旧连续拒写后被误隔离的问题。DrawAI、归藏设计和 Agentero host 的 26 个真实工具通过隔离接口验证，DrawAI 另通过实际文件编辑与 SVG 导出。设计生成、论文 CLI、手机连接和视频渲染仍有各自的依赖与验证边界，详见[插件协作说明](COMPATIBILITY.md)。

外部插件按它们实际注册出来的工具和工作流接入。先按能力选用，第三方工具失败时官方 PTC 工具仍在，并作为兜底。本包不把任何外部插件（包括 dsh-go）写成依赖。

**dsh-go**（手机端，以及手机屏幕控制）在深度 PTC 会话里保持可用：

- 屏幕控制工具留在初始 PTC SDK 里，不收进按需目录，失败后也不隔离。满足下面任一条件即可：工具自己标了 `resident`（或 `deepPtc.resident`）；展示信息带有 `dsh-go/view`；名称是 `intent`、`collect`、`tap_xy`，或以 `screen_` 开头；提供者标记为 dsh-go、屏幕控制、computer use 或手机控制。其他插件也可以用同一个 `resident` 标记把自己留在初始列表。普通扩展仍按需加载。
- 深度 PTC 不声明 dsh-go 自己的槽位，也不替换它的设置表单。表单仍来自 Cordis schema，由应用自己渲染。
- 面板先读自己的状态。投影缺失或会话不属于本预设时，对应部分不显示；面板出错不会拆掉对话、输入区和屏幕控制界面。

本版没有在真机上点过手机屏幕控制。上面保证的是 SDK 成员资格、隔离规则，以及界面投影失败时的退让。

## 1.8.0：会话级 preset 身份兼容

外部插件常用预设 ID 判断是否启用能力。只有用户选择深度 PTC 的会话会做这层适配。DSH 挂载 `deep-ptc`，并将这个预设 ID 写入会话记录。像 dsh-ops 这样依赖官方 ID 的插件通过 `composedPreset` 查询时会收到 `ptc`。

- **第一层（原生）**：不限制预设名称的外部插件拿 `deep-ptc`，直接可用；显式声明支持 `deep-ptc` 的插件也拿原生。
- **第二层（兼容别名）**：调用方规则要求官方预设 ID 时，默认返回 `ptc`。别名只用于这次身份查询。
- 宿主内部必须精确的调用（子代理 header、定时任务、注册表自身）始终拿 `deep-ptc`，不影响继承和调度。
- 普通 PTC 会话本来就返回 `ptc`，其他预设原样返回；官方 PTC 预设没有被替换，也没有改 DSH。
- 创造模式/插件实验台：加载只读宿主的预设清单和文档，不调用 `composedPreset`；实验台挂进深 PTC 会话的创造模式行若只认 `cordis`，第二层就返回 `cordis`，普通创造模式会话仍原样。
- `composedPreset` 每次只返回一个 ID。兼容层根据调用方的包内容或显式配置，在返回前决定用哪一层。宿主没有提供校验结果回调。设置里可用 `presetCompat`、`presetFallback`、`presetSupport` 调整。

局限：这是对 `agentPresets.composedPreset` 的实例包装，依赖宿主内部方法签名；DSH 升级后需要复核。按包内容探测是启发式的，插件如果在代码里用动态拼接的 id，可能识别不到。

## 工作规则

- **不为 token 省力：** 人设写明你拥有 unlimited token、本模式预算无限，按问题需要而不是成本决定读取、搜索、命令和验证的深度；同时禁止注水和啰嗦，单次上下文仍有限，靠压缩、裁剪和子代理控制。
- **任务运行中随时可插话：** 由代码强制（见上文），提示词同时要求：不 sleep、不轮询、不挂长时间前台调用。构建、测试、安装、服务器等耗时命令放后台 job，期间继续做短步骤，用不阻塞的方式查看进度；没事可做就一句话说明在跑什么并结束回合，job 完成会自动唤醒模型，你的消息会被立即处理。
- **按任务长短计划：** ≤5 分钟内部计划直接做，不单独告知；5–20 分钟展示计划后立即执行，不等审批；>20 分钟展示计划并等你批准再改动。估计升档时重新说明计划；显式 plan mode 的规则优先。
- **意图不清先问：** 意思归用户，事实归工具。不认识的名称、多个可能目标、技术路线、权威来源、做事方式、验收标准和范围不确定时先问，不用搜索去猜你的术语；文件位置、当前行为、版本等可检查的事实自己查。每次 1–3 个带选项的问题，推荐项在前；你的回答优先于模型推断。
- **进度可见：** 每次 `run_code` 前一句话说明要做什么，里程碑稍长汇报，连续两三个工具调用必须出声。
- **充分验证并停止，按需委派：** 验证改动触及的行为和边界，满足验收标准后交付；只在任务确实可拆分或需要独立复核时委派，按实际工具渠道收集结果。

提示词能改变模型的工作倾向，但不改变实际的 token 上限或计费，也不保证模型每次完全遵守。真正影响思考深度的设置是模型的 `reasoningEffort`。

## 安装和升级

要求 Node `>=24`、DSH `>=0.2.2-rc.1`。使用 `0.2.1-rc.5` 时，安装器会根据插件清单拒绝安装当前版本。macOS/Zsh 分支做了配置、工具挂载与参数测试，尚未在 macOS 真机执行。

本地目录或构建产物可通过插件管理器安装：

```js
plugin_manager({ action: "install_bundle", target: "dsh-deep-ptc-mode@1.9.2" })
// 也可从本地目录或安装包安装：
plugin_manager({ action: "install_bundle", target: "C:\\path\\to\\dsh-deep-ptc-mode" })
// 或 target: "C:\\path\\to\\dsh-deep-ptc-mode-1.9.2.tgz"
```

GitHub 地址：`github:lishize20040802-rgb/dsh-deep-ptc-mode`。该地址安装远端实际内容；本地升级不会自动发布到 GitHub/npm。

已有旧版时，安装同一个 bundle 即更新。从只有 persona 的旧版切到 1.3.0，需要宿主重新加载插件；桌面端若未出现设置卡片，可重新打开应用。安装不会将其他新任务的默认模式改为深度 PTC。

设置持久化到当前 profile 的 Cordis patch：

```yaml
- id: deep-ptc-settings
  config:
    environment: wsl        # auto | wsl | powershell | zsh | bash
    wslDistribution: Ubuntu # 留空为 Windows 默认发行版
    shellExecutable: ''     # 留空沿用官方查找
```

旧 profile 里的 `pluginLab` 键会被接受但忽略；创造模式读不到或进入安全模式时，会话仍只使用 PTC 工具。

优先使用界面保存，宿主会处理版本冲突和原子配置写入。

## 模式隔离

运行期功能服务于当前选择为 `deep-ptc` 的会话。工具目录、工具状态和执行环境由 Deep PTC 预设挂载。Skill 投影从创建头初始化，并处理宿主合法的 `agent-preset/selected` 事件。命令、`agent/pre-step` 和客户端面板核对当前选择，普通模式的 Skill 状态保持为空。创建头缺失时投影初始为未激活。

## 兼容性与维护

Deep PTC 在加载时依据已安装 Harness 声明的 PTC 预设（`@deepseek-ai/dsh-web-app/presets/ptc.patch.yml`）现场组合：官方行原样继承，仅替换 persona 文本、把两个互斥 shell 工具换成一个带 `shell` 隔离的执行组、加入可达性守卫，并包装官方 job 与提问工具。包装层和执行组自身不写死任何官方模块名：加载的都是官方行里写的模块（shell 执行器取自基础部署声明 `@deepseek-ai/dsh-base/cordis.patch.yml`），并沿用官方配置。官方怎么改 PTC，本模式无需发版即可继承；官方改名或删除的模块也不会留下失效行。所选执行环境无法对应到官方行时，保留官方 shell 行并在日志中说明。只有在该声明无法解析、读取或解析失败时，才退回内置的 `lib/preset.json` 快照，并在日志中说明。

官方声明通过宿主运行时解析，因此插件静态引用的宿主包都必须声明在 `peerDependencies` 中（包括 `@deepseek-ai/dsh-web-app`）：对 `link:` 本地安装，宿主只有看到 peer 声明才会把这些包名路由到已安装运行时。漏声明时 `npm run check` 会失败——这正是避免本地安装静默退回快照的关键。`compatibility.json` 记录 fixture 所取自的上游版本及其哈希；`npm run check` 会验证内置回退快照与 fixture 仍组合出同一预设，并检查继承不变量。`engines` 是安装下限，不能证明之后所有宿主都经过测试，遇到新版本先用 `npm run check:upstream -- <path>` 复核。

```sh
npm ci
npm run check
npm test
npm run check:upstream -- /path/to/ptc.patch.yml
npm run sync:snapshot                      # 从已安装声明刷新 lib/preset.json 与 lib/base-snapshot.json 回退快照
PTC_RUNTIME_MODULES=/path/to/dsh/node_modules node scripts/check-preset.cjs  # 用真实运行时检查每行模块可解析
PTC_RUNTIME_MODULES=/path/to/dsh/node_modules node scripts/check-reachability.mjs  # 用真实运行时验证可打断等待
npm pack
```

检查器把 `!!js` 当数据解析，并断言派生不变量：除 persona、shell 行与两个包装行外，官方行必须原样保留（官方把它们嵌进 group 时也同样处理）；行 id 唯一；九种平台/环境组合下派生结果确定。测试同时覆盖未来可能出现的组合变化（新增未知行、调整行顺序、删除 shell 行或包装行），以及平台选择、命令边界、受限 WSL 拒绝、设置表单原子保存及并发版本约束。真实任务评测仍应记录成功率、无必要提问、范围控制、后台收尾和耗时。

## 文件和卸载

- `cordis.patch.yml`：宿主设置入口。
- `lib/index.mjs`：配置 schema、preset 注册和版本切换。
- `lib/model.mjs`：平台选择、参数、隔离配置和环境说明，以及从官方声明派生 preset。
- `lib/executor.mjs`：继承基础部署声明里的官方 bash 执行器，实现 WSL/Zsh（执行器类在 `lib/mapped-shell.mjs`）。
- `lib/terminal.mjs`：运行官方声明指定的 shell 工具，等待可被用户消息打断，并提供 Zsh 方言与工具名。
- `lib/jobs-tool.mjs`、`lib/ask-user.mjs`：运行官方声明指定的 job 工具与提问工具，等待可被用户消息打断。
- `lib/host.mjs`：通过已安装运行时解析这些官方模块。
- `lib/guard.mjs`、`lib/rules.mjs`、`lib/sleep-lint.mjs`、`lib/reachable.mjs`：拒绝长暂停与轮询的工具守卫，以及可打断等待的实现。
- `lib/client.js`：中英文设置卡片。
- `lib/upstream.mjs`：定位并解析已安装的 PTC 声明。
- `lib/preset.json`：persona，以及仅在声明不可用时的回退快照。
- `test/`、`scripts/check.mjs`、`compatibility.json`：回归与上游差异检查。

卸载使用插件管理器的 `remove_bundle`，目标为 `dsh-deep-ptc-mode`。本地 link 安装直接依赖源目录，应先卸载再删除目录。
